# Выводы реальной проверки приложения

Собственный Agent владеет историей и вызывает Chat Completions API через
собственный Model/urllib клиент. CLI, JSONL и Telegram — адаптеры к Agent;
SDK агента и облачный fallback отсутствуют.

После увеличения лимитов `verify_day27.py` повторно запущен вне Telegram:
две независимые Agent-сессии, четыре настоящих вызова генерации. В исходной
сессии модель вспомнила «манго», другая сессия ответила «не знаю», после reset
исходная также ответила «не знаю». Counted prompt tokens сверены с actual
usage. Вывод: `articles_recheck.log`; полные traces: `cli_dialogues.jsonl`.

Историческая проверка Telegram подтвердила getMe/getWebhookInfo, polling,
входящий /start и welcome allowlist-пользователю. Это проверка транспорта;
обычная LLM-переписка в Telegram ею не подменяется. Содержание ответов реально
проверено независимо от Telegram через CLI/JSONL, что допускает задание 27.

Agent по умолчанию: optimized 32768/6144; baseline 65536/8192. Telegram
использует инфраструктуру Telegram; полностью локальное общение доступно
через CLI/JSONL. Наличие HTTP200 и сохранение истории не гарантируют
правильность ответа на любой вопрос.

В финальной поставке собственный Agent обновлён до основной версии82; plain
ветка сохранена. Новый RAG quality run относится к дням28–30; эти CLIрезультаты
не перезапускались после улучшения. [Общий отчёт](../../REPORT.md).
