## Что изменилось

1. Удалён общий topic prefix, ухудшавший поиск конкретных формул. Непосредственное
   сравнение cosine scores разных queries заменено weighted reciprocal rank fusion.
   Dense-поиск по Qwen embeddings дополнен собственным BM25.
2. Agent составляет план необходимых частей вопроса и английские поисковые
   запросы. При сравнении статей контекст распределяется между источниками.
3. Четыре опорных чанка расширяются соседями ±1 из канонического текста:
   формулы, определения и пояснения реже разрываются границей чанка.
   Оригинальный индекс недели6, его182 vectors/IDs/UTF-16 spans не изменён.
4. Модель возвращает ID цитат вместо переписывания PDF-текста. Программа
   восстанавливает exact quote, revision, PDF pages и UTF-16 coordinates.
5. Генерация обязана вернуть все части вопроса. Проверяются selected evidence
   и полнота относительно исходного вопроса; допускается одна доработка и
   окончательная проверка. Неподдержанные утверждения удаляются отдельно.
6. Сохраняются все calls, каталоги цитат, review inputs, ошибки, actual
   finish_reason, токены и время. История помогает разрешить follow-up,
   но предыдущие ответы модели не становятся документальными источниками.

Agent и Model — собственные сущности, Chat Completions вызывается напрямую
по HTTP. LangChain, LlamaIndex и agent SDK не используются. Tiel Coder35B-A3B
работает локально через llama.cpp Vulkan; embeddings — Ollama
qwen3-embedding:0.6b,1024D; необязательный reranker — локальный BGE.

## Оптимизация и квантование: историческая матрица

Все80 ответов core37e сохранены;10 одинаковых вопросов × два прохода × четыре
условия. Один слот, исключённый настоящий warmup, seed42, cache_prompt:false.

| Условие | Correct /20 | Неподтверждённые факты /20 | Среднее время, с | Generation tokens/s |
|---|---:|---:|---:|---:|
| A: baseline Q8 | 3 | 5 | 54.75 | 42.41 |
| B: optimized Q8 | 5 | 2 | 56.29 | 42.31 |
| C: baseline Q4 | 3 | 1 | 43.86 | 53.74 |
| D: optimized Q4 | 3 | 0 | 56.59 | 43.35 |

Q8/B унаследован из этого выбора. Улучшение настроек увеличило correct3→5
и уменьшило галлюцинации5→2, но ускорения не дало. Q4 baseline быстрее,
однако его полнота ниже Q8/B. RSS/PSS, host RAM и shared GPU GTT не складываются;
пики измерены sampling около200ms, а не абсолютным аппаратным максимумом.
[Полная таблица ресурсов](day29-optimization/results/comparison.md).

Новый набор20×2 отличается от прежнего10×2: проценты из этих наборов нельзя
считать чистым сравнением до/после. На четырёх известных проблемных вопросах
промежуточный новый вариант дал3/4 correct против0/4 прежнего Q8/B; это
разработка на известном наборе, отдельный source9e297, а не слепой финальный тест.

Текущий planner может менять context при смене quant. Grader теперь явно
разделяет fixed-context и end-to-end сравнение, выбирает generation call по
phase=answer и сохраняет drift plans/queries/evidence/prompts. Историческая
матрица прошла строгую проверку одинакового answer context; новую матрицу
для новой версии после просьбы остановить проверки не запускали.

## HTTPS и роль VPS

Адрес сервиса: **https://95.215.56.217/local-llm**. Клиент общается по HTTPS
с bearer token и штатной проверкой TLS; клиентский SSH-forward не требуется.
НаVPS Caddy и stdlib gateway, наПК Agent/API/Tiel/embeddings/RAG.

Внутренний SSH reverse tunnel предоставляет VPS доступ к loopback API ПК
через исходящее соединение ПК. Он сохраняет синхронный Chat API без входящего
порта ПК. В setup-ocr использован исходящий HTTPS polling worker и очередь:
это потребовало бы отдельного job/poll протокола для чата. NAT не проверялся.

Свежий уже завершённый диалог core82 подтвердил10 HTTPS-запросов и29 фактических
LLM calls по журналу ПК; history/reset, context, usage и provenance согласованы.
В четырёх RAG-репликах основные вопросы отвечены правильно4/4, полностью
поддержаны выбранными цитатами2/4; фактических галлюцинаций не найдено.
Есть обрыв цитаты о recall queue и неудачная цитата для FIFO/recursive summary.
Время RAG-реплик84–228с. [Независимый аудит](day30-private-service/results/quality_v2_https_audit.json).

Сохранённые предыдущие HTTPS проверки:5/5 и10/10 параллельных запросов,
auth401, body413, context422, rate429 и восстановление200; точная граница
prompt26624+reserve6144=32768 принята,26625 отклонён до generation.
Из15 длинных overflow запросов9 завершились200 и6 контролируемым503.
Остановка/восстановление собственной модели и туннеля дала503→200.
Это доказательства соответствующих прежних запусков, не новый повтор core82.

## Практический вывод

Технические условия заданий покрыты исходниками и фактическими запусками.
Улучшенный RAG существенно полнее отвечает на вопросы по трём статьям,
но его нельзя считать безошибочным: остаются неподтверждённые уточнения,
неполная поддержка отдельных цитат и высокая задержка. Облако и веб не являются
автоматическим fallback; Telegram не является полностью приватным каналом.
Для полностью локального режима доступны CLI/JSONL/loopback HTTP с web off.
