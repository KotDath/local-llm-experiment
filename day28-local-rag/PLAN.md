# День 28 — локальный RAG по трём научным статьям

Требования: использовать индекс недели 6, выполнять retrieval и генерацию локально;
сравнить качество, скорость и стабильность с доступной облачной моделью.

## Реализация

1. Скопировать оригинальный индекс недели 6 без изменения байтов: 182 чанка,
   1024-мерные Qwen embeddings. Включить полные PDF и канонические тексты MemGPT
   2310.08560v2, MemoryBank 2305.10250v3, Generative Agents 2304.03442v2.
2. Проверять footer, document hashes, fingerprint, vectors и UTF-16 spans.
   Дополнить источники точными страницами PDF; реализовать свежую пересборку.
3. Собственный Agent обращается к Chat API через urllib. Retrieval: Ollama
   qwen3-embedding:0.6b → NumPy cosine → необязательный локальный BGE reranker.
   Явно названные статьи фильтруются; сравнения получают контекст обеих статей.
4. Tiel Coder генерирует grounded JSON. Проверить IDs и буквальные цитаты;
   выполнить ограниченную проверку полноты и одну доработку ответа. Сохранять
   все вызовы и ошибки. Такая проверка не гарантирует семантическую правильность.
5. Общаться через CLI, JSONL и Telegram; учитывать историю для follow-up,
   сохраняя источниками только документы, а не предыдущие ответы модели.
6. Сравнить M0 без RAG, M1 dense RAG и M2 с BGE на одинаковых 10 вопросах.
   M1 берётся из B/repeat0 дня 29, второй проход B оценивает стабильность.
7. Отдельно вызвать deepseek-flash через HTTP с тем же собственным Agent и
   публичным контекстом; не включать cloud fallback в обычный локальный режим.
8. Необязательный verify.py проверяет байты закреплённых PDF и последнюю версию
   на arXiv. Это проверка актуальности документов, а не научной истинности.

## Проверка улучшения качества v2

Предыдущие результаты core37e сохранены в `results/history-quality-v1/source`
и исходных raw logs. Новая версия использует hybrid dense/BM25 RRF, соседние
чанки, план частей вопроса, ID цитат, одну доработку и окончательную проверку.
Новый независимо подготовленный набор — 20 вопросов × два прохода; только
question попадает в Agent, expected facts не входят в prompt. Оценка связана
с SHA фактически выданного ответа. Цель: ≥80% correct и отсутствие
неподтверждённых фактов; достижение определяется независимой оценкой, а не HTTP200.
Фильтр лишних фактов проверен отдельным paired экспериментом и отклонён:
34/40 correct против36/40, два ухудшения, число неподтверждённых фактов то же3. Статус и итоговые ограничения: [QUALITY](../QUALITY.md).

Итог: основной вариант36/40 correct, три ответа с неподтверждёнными фактами;
цель ≥80% выполнена, цель0неподтверждённых фактов не достигнута.
Новых проверок после завершения этой серии не запускали. [Отчёт](../REPORT.md).
